# Git integration

Git operates on saved project files in a standalone repository with `purr.yaml` at its root. Editor working copies, tabs, responses, history and credentials retain their existing local/secret owners. Git never projects the runtime workspace into a second persistence format.

The application-owned `GitPort` crosses typed native IPC, including status subscriptions. The native adapter invokes system Git (2.38+) with argument arrays, bounded output and cancellation. HTTPS access uses the system credential helper; SSH uses the existing agent in batch mode. Remote URL credentials are rejected on input and redacted from diagnostic output. Browser adapters must report Git as unavailable.

Status uses Git's porcelain v2 NUL-delimited protocol, preserving separate index and working-tree states, paths containing spaces and rename pairs. Text previews compare actual blobs and working files; binary or oversized content receives metadata instead. Repository paths cannot escape the root, traverse symbolic links, or modify `.git` through file actions.

The canonical workspace ID remains the identity boundary. Nested projects, linked worktrees and submodules are outside this integration's supported repository layout.

## Saved changes and operations

Initialization appends missing system/editor ignore rules without replacing user rules. It does not stage or commit files automatically. Stage/unstage preserves the real index; commits validate the complete staged canonical tree, including workspace identity and referenced sidecars/assets. A staged version remains independent from subsequent working-file edits. Stage/unstage runs through the save queue without a canonical rescan or a workspace-wide interaction lock; optimistic rows are reconciled with the confirmed native index and rolled back on failure. Discard restores selected working files from the index and removes selected untracked files only after confirmation and complete-project dependency validation.

Native validation combines the credential/format inventory with the JSON Schema generated from the canonical Zod schemas, plus cross-resource uniqueness, folder-cycle, variable/profile and asset checks. Regenerate `src-tauri/schemas/project.json` with `npx tsx scripts/generate-project-schema.ts --write` after schema changes; a TypeScript test rejects stale generated schemas. The JSON Schema validator has external file/HTTP resolution disabled.

Pull uses fetch and merge with explicit policy: fast-forward when possible, merge when histories diverge, never rebase or force push. A target with a different workspace ID or no common ancestor is rejected before changing the worktree. Empty remotes accept the initial push. Branch switching validates the target workspace first. Dirty trees require explicit continuation; Git still refuses overwriting changes.

Before merge, switch or stash application, Purr records an encrypted recovery checkpoint of the original index, dirty files and file fingerprints. A failed or conflicted operation retains the checkpoint. Abort restores only when the entire current post-operation fingerprint still matches, so later external edits are preserved. Stash application retains its stash until successful validation or conflict completion. Untracked assets are restored separately: identical existing bytes are retained, differing files are refused, and missing files are created without replacement. Stash completion validates the complete working project; it does not require the intentionally partial restored index to contain every asset. Only committing a merge requires a complete staged project. Git conflict editing uses expected file revisions and validates the entire resolved project before completing the merge.

Cancellation reaps the Git process before releasing its lease and records the resulting recovery state even when the cancellation token has fired. On Unix its process group also terminates SSH/helper/hook children. Ignored files are protected during merge and switch. Unresolved external rebases and cherry-picks require completion in the external Git client.

## Native coordination and restart

Native Git IPC is restricted by the same trusted-main-webview guard as persistence. A per-workspace lease prevents concurrent Git mutations and canonical saves without holding SQLite during network access. File-changing completion emits the normal full project rescan and a separate Git-status invalidation, including on failure. Index-only changes emit Git-status invalidation without reloading canonical files. The watcher also invalidates status for external worktree/HEAD/index/ref changes, ignoring object/log churn.

The version-1 `workspace_local_state/git-operation` record is encrypted and owned by the native Git adapter. Normal projection preserves it. While it exists, startup restores the pre-operation canonical snapshot and local working copies in recovery mode; partially merged YAML cannot prevent the workspace opening or be overwritten by autosave. Resolve/finish/abort remain available through Git IPC without first attempting a canonical save. This Git recovery gate is independent of protected-storage availability: credentials retain their actual vault state, and an unchanged canonical snapshot still clears the gate when its checkpoint is removed.

Clone uses a temporary sibling directory, validates the complete project and workspace identity, then publishes into a new or empty destination. An empty clone destination requests the native managed `projects/<validated-workspace-id>` location; an explicit picker destination remains external. The directory-info response also exposes the native projects parent for display. The existing open-directory pipeline accepts the exact managed identity path while rejecting other private storage paths. A duplicate registered workspace ID is rejected. The selected project is subsequently registered through the existing revision-checked open-directory pipeline.

## Semantic and file diffs

Diff preview offers Semantic and exact YAML views. Semantic parsing uses the canonical codecs, so omitted defaults and YAML formatting do not create false field changes. Requests show method alongside URL, ordered query/path/header rows, auth, body fields, GraphQL, settings and documentation. Stable row IDs retain duplicate and disabled rows, match renames independently of names, and distinguish reordering from insertion. Without a stable ID, exact copies and unique unchanged names can be paired; ambiguous duplicate edits and unmatched renames remain removals/additions. Legacy codec-generated positional header IDs are excluded from preview matching without changing stored files. Environments, workspace definitions, folders, schemas and opaque extension config use the same canonical boundary. Credential previews display references without reading SecureStore. Info groups identity metadata into a compact disclosure. Named parameter/header/variable and body-field tables keep one entity per row: the name column shows a compact old → new rename, and the value columns compare Before/After. Enabled/secret state remains visible beside the values. Dynamic variables compare complete extraction recipes: source request, expression, language and refresh/environment context. Authentication presents a scheme with compact credential rows; Body presents its format and payload or attachment together. New-file previews omit empty optional configuration. Semantic panels keep unchanged text neutral. Added/removed fields use compact row indicators and neutral values; renames stay in the name column without introducing property rows. Multiline code matches GraphQL selections by nested identity, JSON properties by name and XML elements by tag. Unmatched lines receive subtle line status; inline marks are limited to edits within matched lines, without coloring surrounding quotes or whitespace. Complete payload replacements, including JSON → XML, retain each side’s syntax palette and use block-level indicators instead of fragmented token marks. Scalar changes stay in compact rows; multiline payloads share aligned line rows, and table cells are vertically centered, including recipes, badges and credential placeholders. Query rows mirrored in a request URL are compared once in the parameter table. Exact YAML marks removed lines/text in red and added lines/text in green. Added/deleted files use normal syntax in a single content preview with a file-level status indicator, including empty files distinguished by explicit existence metadata. New/deleted SDL schemas show a compact entity summary and member counts, lazily rendering members only when an entity is expanded.

GraphQL request comparison parses operations to ignore formatting-only changes while preserving field, argument and selection ordering. Token comparison keeps unchanged selections neutral; invalid/incomplete content falls back to bounded text comparison. Variables JSON is compared as data and formatted for individual value highlighting. Read-only semantic code uses the same GraphQL/JSON parser tags and syntax palette as the editors, without mounting editor instances. SDL sidecars have structural semantic views keyed by type, field, argument, enum value and union member names; descriptions, directives, nullability and list changes remain attached to their entity. Only changed entities/members are shown by default, with a reveal-unchanged option. SDL text previews retain exact files with syntax highlighting, line numbers and folding, including single-sided added/deleted content. Comments and formatting remain inspectable in Text mode; semantic comparison is syntactic and does not infer breaking-change compatibility.

CodeMirror's merge view renders real before/after file contents with Purr's editor theme; conflict editing adds source-to-result chunk controls. Binary or oversized previews show metadata. Unknown files fall back to the text view.

## Interaction decisions

[Bruno's Git UI](https://docs.usebruno.com/git-integration/using-gui/intro) separates file review, staging, history, stashes and remotes, and supports structural diff review and conflict editing. Purr uses that structure in a dedicated Source control rail activity, retaining document tabs in the Documents activity. Git subviews share one Overview navigation position. The sidebar keeps commit controls above the staged/working file groups. Commit still includes staged changes only; tooltips and accessible descriptions explain that scope and disabled states without extra helper rows. Disabled Commit uses a neutral surface. Resource types and folder names replace UUID paths in the visible list, with exact Git paths retained in tooltips and accessible labels. The top-aligned overview uses the Purr application icon and summarizes branch, upstream, remotes, ahead/behind counts, saved changes and recent commits; Git actions remain in the sidebar. Empty staged groups are hidden; plus/minus actions stage or unstage files, and hover actions open owning documents or discard changes. Stash creation is in the commit dropdown; the Stashes view applies or drops saved entries. [Yaak's directory sync](https://yaak.app/docs/collaboration/local-directory-git-sync) watches both directions and asks for confirmation on incoming filesystem changes. Purr adopts bidirectional watching while refreshing clean editors immediately; confirmation is scoped to dirty editors whose base changed. This preserves the existing saved-versus-working-copy lifecycle without interrupting every clean pull.

| State | Pull / switch behavior |
| --- | --- |
| Pending persistence | Flush before starting Git |
| Clean saved files | Proceed after project/identity/history validation |
| Dirty compatible saved files | Warn; explicit Continue lets Git preserve them |
| Files would be overwritten | Git refuses; offer Commit, Stash or Cancel |
| Dirty editor changed by incoming files | Preserve local editor and incoming baseline; explicit review |
| Deleted active clean document | Select next surviving tab, then previous |
| Unresolved merge or pending checkpoint | Block new pull/switch; Resolve, Finish or guarded Abort |

The native shape validator uses the [jsonschema crate](https://docs.rs/jsonschema/0.56.0/jsonschema/) with external retrieval disabled. Diff and result editing use CodeMirror's merge package through Purr's existing editor theme.
